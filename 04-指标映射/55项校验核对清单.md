## 四、关键发现（本体工程视角）

### F1（⚠ 需拍板）`computedFrom` 值域口径——"复用实体"不是 `DataObject` 实例

- `属性与关系.md` §一 现定义：`computedFrom : Indicator → DataObject`。
- 但 §2.8.1 明确"**复用类**（住宅 / 小区 / 危旧房 / 老旧街区 / 厂区 / 城中村 / 体检问题 / 更新项目）**不新建 `DataObject`**"——它们是 `SpatialUnit` / `RenewalObject` / 主干类的实例。
- 录入模板把这些复用类写进了"涉及数据对象"列（指标 1 = `SpatialUnit.Building`、16 = `SpatialUnit.ResidentialQuarter`、24 = `RenewalObject.OldBlock.OldCommercialBlock`、40 = `RenewalObject.UrbanVillage`、54 = `Problem`、55 = `RenewalProject`）。
- → 若 `computedFrom` 值域**严格取 `DataObject`**，这些指向**违反值域**。三者必须选一：

| 选项 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | `DataObject` 升为**抽象角色类**；`computedFrom` 值域 = `DataObject ∪ SpatialUnit ∪ RenewalObject ∪ Problem ∪ RenewalProject`（OWL：`owl:unionOf`；SHACL：`sh:or`） | 语义干净，"数据对象"= 被指标引用的输入角色，兼容两类实例 |
| B | 把复用实体声明为 `DataObject` 子类（`rdfs:subClassOf`） | 可行但 `Building` 会同时属于 `SpatialUnit` 与 `DataObject`（多重继承），OWL 允许、稍绕 |
| C | 拆两条关系：`computedFrom`(→DataObject) + `derivedFrom`(→复用实体) | 增加关系数，**不推荐** |

### F2 命名风格待统一（D4 已定，执行时处理）

录入模板数据对象名**带前缀**（`SpatialUnit.Building`、`Land.ResidentialLand`、`RenewalObject.OldBlock.OldCommercialBlock`），§2.8.2 实体表用**裸 URI 名**（`ElderlyCareFacility`、`MiddleSchool`…）。导出 `55项指标.yaml` / `.ttl` 时统一取**裸 URI 名**（D4 已定）。需转换的前缀：`SpatialUnit.*` → 子类名、`Land.*` → 子类名、`RenewalObject.*` → 更新对象子类名。

### F3 覆盖率中间量处理（确认无违背）

19/22/27/48 的"覆盖居住用地面积"等中间量**未单列** DataObject，由"设施服务半径 + 居住用地"空间叠算得出，符合 2026-09-24 决议（覆盖率中间量不单列）。

### F4 数据对象三分类已落实

录入表"涉及数据对象"列已体现 §2.8 三类：**复用实体**（住宅/小区/城中村/问题/项目等）、**实体对象**（各类设施/场所/用地/事件）、**基础量**（建成区面积/常住人口数/城市道路长度等）——与 §2.8.1/2/3 一致，0 冲突。
