# 城市体检与更新本体 · 高保真原型（阶段一）

> 阶段一交付物：**静态单页应用**，零外部依赖，双击即开。
> 架构按「方案 C 可演进的本体工作台」的三层骨架搭（数据 / 查询-推理 / 视图-智能），
> 阶段一只落**视图层 + 静态数据**，后端留空——阶段二在原架构上叠加查询层与智能层，不必重构。

---

## 一、怎么跑

**方式 A：直接双击** `index.html`（推荐）
数据通过 `data/ontology.js` 以 `<script>` 方式加载，`file://` 协议下可直接打开，**离线可用**。

**方式 B：起本地服务**（数据量增大或要跨设备访问时）

```bash
cd 05-产出/原型方案/原型
python -m http.server 8080
# 浏览器打开 http://localhost:8080
```

> 注意：**不要**用 `file://` + `fetch()` 的方式取 `ontology.json`（会被 CORS 拦），
> 所以本原型走 `ontology.js` 注入路线；`ontology.json` 供阶段二的查询层/后端使用。

## 二、URL 参数（便于分享指定视图）

| 参数 | 取值 | 说明 |
|---|---|---|
| `view` | `graph` \| `matrix` \| `backbone` | 直接进入指定视图，默认 `graph` |
| `focus` | 类 URI 名，如 `SpatialUnit`、`Indicator` | 打开即**聚焦缩放**到该类（不传则进全量总览） |
| `abox` | `1` | 打开即叠加 ABox 个体（199 节点） |

例：`index.html`（总览）、`index.html?focus=Indicator`、`index.html?abox=1`、`index.html?view=matrix`

## 三、已实现的功能

| # | 功能 | 说明 |
|---|---|---|
| 1 | **类层级树** | 按**语义域**分组（主干闭环 / 指标内核 / 指标双轴 / 空间主轴 / 更新要素 / 政策依据 / 通用 / 支撑类），可逐级展开；ABox 个体以浅色子项列出 |
| 2 | **全局检索** | 同时过滤类层级树与命中计数 |
| 3 | **详情卡** | 类：定义 / 来源 / 下位类 / 实例 / **关联指标** / 属性（定义域 + 被引用）/ 标识；属性：定义域与值域；指标：维度 / 分类 / 层级 / 单位 / 导向 / 计算方法 / 阈值 / 依据 |
| 4 | **知识图谱** | **打开即全量总览**（107 个类 + 83 条 `subClassOf` + 5 条主干闭环边），按语义域聚类成团、自动取景；**点任一实体 → 平滑聚焦缩放**（原点与邻居按距离依次「颤动」一下，形成涟漪感）、高亮其邻居、右侧出详情；滚轮缩放 / 拖空白平移 / 拖节点微调；**`overall 总览` 一键回到全局**；`显示 ABox 个体` 可叠加 92 个个体（共 199 节点） |

> **图谱视觉细节（2026-10-12 修订）**
> - **字号与线宽屏幕恒定**：字号用 `calc(基准 / 缩放 / 屏幕比例)` 反算、描边用 `vector-effect:non-scaling-stroke`，所以放大缩小时字不变大、线不变细。
> - **标签单独成层、永远画在最上**（否则会被别的节点圆盖住），并按中文全角宽度估算包围盒做**自动避让**，重叠的优先保顶层类与聚焦邻居。
> - **动效交给 CSS 过渡**（`#world` 的 `transform` transition），平移/拖拽时临时加 `.nofx` 关闭过渡以保持跟手。
| 5 | **指标双轴矩阵** | 13 分类 × 5 维度交叉表，格内为指标数，**按维度着色**；点格查看该格指标清单 |
| 6 | **主干闭环视图** | 体检活动 → 评估结果 → 问题短板 → 整治建议 → 更新项目，含 `triggers` 直通兼容路径；点卡片回图谱 |

## 四、数据来源与更新方式

**唯一数据来源**：`03-本体模型/_to_graph_json.py`（生成器）。
它读取三个同源文件并产出 `data/ontology.json` + `data/ontology.js`：

```
城市体检-更新本体.ttl ──┐
类与层级.md ────────────┼─→ _to_graph_json.py ─→ data/ontology.json / ontology.js ─→ 前端
55项指标.yaml ──────────┘
```

**改了本体后**，重跑一次即可（前端无需改动）：

```bash
python 03-本体模型/_to_graph_json.py
```

生成器带**防漂移断言**，任一不满足即报错退出：

1. `类与层级.md` §一 的 16 个顶层类必须都能在 ttl 中找到；
2. 六域映射（`DOMAIN_OF`）必须覆盖全部顶层类；
3. ttl 中 `Indicator` 个体数必须等于 yaml 指标数、序号恰为 1..55；
4. **ttl 中"被 `rdfs:subClassOf` 引用但未声明"的类，必须都能在 md 中找到中文名**；
5. 每个类必须有 `rdfs:label`（中文标签）。

## 五、数据缺口处置记录（已闭环）

**⚑ 2026-10-11 已修复**：早前 `_to_graph_json.py` 运行时会报出——

```
[WARN] ttl 未声明的父类：EventObject, FacilityObject, HeritageObject, Land,
       LineObject, ManagementObject, SpaceObject
```

这 7 个类被 `rdfs:subClassOf` 引用，却在 `城市体检-更新本体.ttl` 中未被声明为 `owl:Class`。
根因是 `03-本体模型/_gen_ttl.py` 的 `SUB` 字典里有一处**重复键** `"DataObject": None,`
（Python 重复键取末值），把 `DataObject` 的 7 个分类父类声明行整个覆盖掉了。

**处置**（经大王确认，属结构性变更）：

1. 删除该重复键，7 类归位为 `DataObject` 子类 → `.ttl` 类数 **100 → 107**；
2. `_gen_ttl.py` **新增反向防漂移断言**——凡被当作父类、或被属性定义域/值域引用的类必须已声明，否则构建失败（已做负向测试：复现旧写法会被精准拦截，且不写出产物）；
3. 本导出器的 `warnings.undeclaredParents` 相应归零，原型中的**虚线框 / `!` 角标 / 页脚告警均已自动消失**。

> 现在 `[WARN] ttl 未声明的父类：` 一行为空，属**正常状态**。
> 另注：`DataObjectRoleUnion`（`computedFrom` 值域的 `owl:unionOf` 包装类）是**技术构件、非概念类**，已在导出器中标 `role=technical`。

## 六、与阶段二的接口（已预留）

| 阶段二能力 | 本阶段的接口点 |
|---|---|
| SPARQL 查询层 | 前端所有数据访问都经 `D`（`window.__ONTOLOGY__`）单一入口；阶段二把 `D` 替换为 API 返回值即可，视图层不动 |

| 智能应用 | 顶部视图切换区可增「诊断 / 建议」按钮，复用同一详情面板与图谱渲染 |
