## 一、设计意图

原版问题是**一屏之内只有相近色**（墨绿 + 橙），所有节点靠同一种色系，形状又都是圆点，导致：

- 节点之间**无区分度**——看不出哪些属于同一个语义组；
- 长时间查看**视觉疲劳**——没有层级、没有焦点。

对策不是「多加几个颜色」，而是先**按本体语义把节点分成 6 个域**，每域固定一个色系；再用**填充方式**（实心 / 浅底 / 透明）表达层级，而不是靠颜色深浅。这样颜色承载的是**语义**，不是装饰。

---

## 二、六域色板

| 域         | 中文名      | 语义范围（本体类）                        | 主色        | 浅底        | 深色主题档     |
| --------- | -------- | -------------------------------- | --------- | --------- | --------- |
| `core`    | **主干闭环** | 体检活动 / 评估结果 / 问题短板 / 整治建议 / 更新项目 | `#185FA5` | `#E6F1FB` | `#5AA3E8` |
| `metric`  | **指标内核** | 体检指标 / 数据对象                      | `#534AB7` | `#EEEDFE` | `#9C93EE` |
| `axis`    | **指标双轴** | 指标维度 / 指标分类                      | `#0F6E56` | `#E1F5EE` | `#4CC79E` |
| `space`   | **空间主轴** | 空间单元（城区 / 街区 / 社区 / 小区 / 建筑）     | `#993C1D` | `#FAECE7` | `#F0865C` |
| `renew`   | **更新要素** | 更新对象 / 更新方式 / 行动主体 / 资金          | `#3B6D11` | `#EAF3DE` | `#9FCB5C` |
| `policy`  | **政策依据** | 政策标准                             | `#854F0B` | `#FAEEDA` | `#EFB44A` |
| `neutral` | 通用       | 时间周期等未归类项                        | `#5F5E5A` | `#F1EFE8` | `#A8A69D` |

> **色相选择逻辑**：主干闭环取**蓝**（与「水/流程」直觉一致，且是政务与科技场景的中性主色）；指标双轴取**青绿**呼应「度量/校准」；空间取**珊瑚红**（土地/建成环境的暖色联想）；更新要素取**草绿**（实施/生长）；政策取**琥珀**（文本/权威）。六色相在色环上间隔充分，并排不易混淆。

## 三、用法规则

**层级由「填充方式」表达，不由颜色深浅表达：**

| 元素                           | 处理                                     | 说明                        |
| ---------------------------- | -------------------------------------- | ------------------------- |
| 主干闭环节点                       | **实心主色 + 白字**                          | 全图**唯一**允许实心的域，构成视觉焦点     |
| 其他域节点                        | 浅底 + 主色描边 1.6px + 主色文字                 | 有色彩但不抢镜                   |
| 空间子级（城区/街区/社区/小区/建筑）         | 透明底 + 主色细描边 1px（65% 不透明）               | 层级更弱，避免与主节点混淆             |
| 主干闭环的边                       | 主色 2.2px                               | 把「体检→问题→建议→项目」画成一条看得见的主管道 |
| 其余边                          | 中性灰 1.2px                              | 退到背景                      |
| 直通兼容路径（`triggers`）           | 中性灰**虚线**                              | 语义上就是「非必经」                |
| 树徽标 / 详情域标签 / URI 块 / 详情顶部色条 | 一律取**所属域**的色                           | 左右面板与图谱同色，形成对应关系          |
| 维度条（五级）                      | 各占一色：住房→蓝 / 小区→紫 / 社区→青 / 街区→绿 / 城区→珊瑚 | 一屏内直接看出维度分布               |

**主色顺序**：一屏内先主干闭环（蓝），再其他域——保证视线第一落点永远在主干链路上。

### 补充：画布深色（混合版）

界面浅色、**画布深色**，两者靠「作用域变量」解耦——深色档域色只下沉到 `.canvas`，不污染其余面板：

| 元素                              | 处理                                              |
| ------------------------------- | ----------------------------------------------- |
| 画布底色                            | `#101820` + 白色 7.5% 点阵网格                        |
| 画布内域色                           | 一律取**深色档**（提亮 + 半透明底），色相与浅色档一致                  |
| 画布内边线                           | `#33465c`（浅色界面的 `#c9c9c1` 在深底上看不见，必须换）          |
| 画布内边标签                          | `rgba(255,255,255,.52)`（同理，不能沿用浅色界面的 `--text3`） |
| 图例                              | 转为**深色控件**（白色 7% 底 + 14% 边框 + 浅色文字），色块仍取深色档域色   |
| 界面其余部分（页头 / 类树 / 详情 / 页脚 / 维度条） | 全部保持**浅色档**，不受画布影响                              |

> 这样做的收益：浅色面板长时间阅读不刺眼，深色画布让彩色节点与主干链路更跳——两种需求各得其所。**关键是不可让深色档泄漏到面板区**，否则界面会花。

## 五、约束（红线）

1. **不引入与域语义无关的装饰色**——每个色都必须能回答「它代表哪个域」。
2. **同屏主色不超过 6 个域 + 中性**；新增概念须先归入已有域，确需新域再讨论。
3. **深浅主题只调明度，不改色相**——域色是「身份」，跨主题必须可辨认。
4. **颜色不单独承载信息**——节点始终带中文标签，颜色只作辅助（色觉障碍可用）。
5. 节点形状暂统一为圆，「实心 / 描边」表达层级；若后续要加形状编码，须另立一版规范。
6. **深色档域色只允许出现在 `.canvas` 作用域内**——一旦泄漏到面板区，浅色界面的对比关系会被破坏；新增画布内元素时必须确认其颜色继承自画布作用域。
