### 三-3 新增约束

- [x] `Problem.problemCategory` **枚举**：取值 ∈ {经济, 社会, 生态}（`owl:oneOf`）。
- [x] `Problem.severity` **值域**：**数值 [0,1]**（`sh:minInclusive 0` / `sh:maxInclusive 1`）；三档为档位映射，非独立枚举（2026-10-09 批注 Q1 改）。
- [x] `RemediationSuggestion.treatmentType` **枚举**：取值 ∈ {限时解决, 尽力解决}（可多选，`owl:oneOf`）【待核：判定规则】。
- [x] `Problem.derivedFrom` **基数**：1..1（每条问题由且仅由一条评估结果导出）。
- [x] `Problem.locatedIn` **约束**：必填（问题必须绑空间单元，`sh:minCount 1`）；不参与 `locatedIn` 传递闭包。
- [x] `Indicator.inCategory` **基数**：0..1（问题整治 54、55 无分类；其余 53 项各有 1 个分类）。
- [x] `ProblemIndicatorMapping.mappingWeight` **区间**：∈ [0, 1]（`sh:minInclusive 0` / `sh:maxInclusive 1`）。
- [x] `evaluatedBy` **基数**：带 `threshold` 的 `Indicator` 可挂 1..n 个 `EvaluationRule`。

## 四、约束与公理（对应 SHACL 导出）

以下约束是本体"可计算"的关键，后续写入 `城市体检-更新约束.shacl`：

- [x] `locatedIn` **传递性**：若 A locatedIn B 且 B locatedIn C，则 A locatedIn C（OWL：`owl:TransitiveProperty`）。小区 locatedIn 社区、社区 locatedIn 街区、街区 locatedIn 城区据此传递。**例外（2026-10-09）**：`Problem` 虽扩入 `locatedIn` 定义域，但**不参与传递闭包**（问题指向具体空间单元即止，不再向上归并）。
- [x] `produces` **函数性**：一个 `AssessmentResult` 必须且只能由一个 `ExaminationActivity` 产生（`owl:FunctionalProperty` 式约束）。
- [x] `triggers` **基数**：一个 `Problem` 可触发 0..n 个 `RenewalProject`（`sh:minCount 0`，`sh:maxCount 无上限`）。**2026-10-09 补充**：`triggers` 现为**直通兼容路径**，主干正路为 `Problem --proposes--> RemediationSuggestion --leadsTo--> RenewalProject`；二者可并存，不互斥。
- [x] `proposes` / `leadsTo` **基数（2026-10-09 新增）**：`Problem.proposes` 基数 1..n；`RemediationSuggestion.leadsTo` 基数 0..n（建议可能尚未立项）。
- [x] `assignedTo` **基数（2026-10-09 新增）**：`RemediationSuggestion.assignedTo` 基数 1..n（责任单位可为多个）。
- [x] `measures` **层级匹配**：`Indicator.measures` 只能指向其 `inDimension` 对应的空间层级（住房维度 → `Building`、小区维度 → `ResidentialQuarter`、社区维度 → `Community`、街区维度 → `Neighborhood`、城区维度 → `UrbanDistrict`）。跨级采集须在映射表显式标注。
- [x] `threshold` **版本绑定**：凡带 `threshold` 的 `Indicator`，必须存在 `basedOn` 指向一个带 `policyVersion` 的 `PolicyStandard`，否则 SHACL 校验失败（防止阈值硬编码 / 来源缺失）。
- [x] `computedFrom` **基数**：`Indicator.computedFrom` 至少指向 1 个数据对象（`sh:minCount 1`）；指标不得无数据对象凭空存在。
- [x] `computedFrom` / `feedsInto` **值域 = 角色类（2026-09-29 决议 A）**：`DataObject` 为**角色类**（"被指标引用的输入项"），值域 = `DataObject ∪ SpatialUnit ∪ RenewalObject ∪ Problem ∪ RenewalProject`（OWL：`owl:unionOf`；SHACL：`sh:or`）。§2.8.1 复用实体（住宅 / 小区 / 城中村 / 老旧街区 / 体检问题 / 更新项目）不新建 `DataObject`，直接作值域成员；`feedsInto` 定义域同步放宽。
- [x] `formula` **完整性**：凡 `computedFrom` 指向 ≥2 个 `DataObject` 的 `Indicator`，必须同时带 `formula`（`sh:minCount 1`），否则无法计算组合结果（单对象指标 `formula` 可简写为统计方法）。
- [x] `belongsToDimension` **基数（2026-10-10 新增·折中方案）**：每个 `IndicatorCategory` 至少归属 1 个 `Dimension`（`sh:minCount 1`），**允许一对多**（如「设施完善」同归社区维度 + 小区维度）；分类轴仍与 `Dimension` 平行独立，本关系仅显式记录归属（决议见 `类与层级.md` §2.10.3）。

## 五、已知风险

- **`measures` 关系是本体的成败点**。体检指标天然分属不同空间层级（有的在城区、有的在小区/社区），若层级绑定关系定义不清，指标映射会全线失效。§三 第 4 条约束即为此设（已同步五级维度）。
- **阈值类数据属性极易过期**，必须与 `PolicyStandard`（带 `policyVersion`）绑定并标注版本，不可硬编码在模型里。
- **维度口径已决议（2026-09-20）**：五级维度（住房 / 小区 / 社区 / 街区 / 城区），小区默认 `locatedIn` 社区；`Dimension`、`SpatialUnit` 子类、`measures` 约束已同步五级。
- **`Building`（建筑）≠「房屋安全体检」**：本体的「建筑」是城市体检口径的物理建筑实体（承载建成年代 / 建设阶段 / 绿色建筑属性），**不是单体建筑结构安全鉴定**；凡"新建建筑"类表述一律由属性判定，不得另建"新建建筑"类（大王批注 2026-09-28）。
- **派生量不单列 `DataObject`（2026-09-28 批注）**：`居住用地面积` / `建设用地面积` / `新开工建筑总面积` 均由实体类属性聚合得出（`Land.*.landArea` / `Building.floorArea`），`computedFrom` 应指向对应实体类，不得凭空生造对象。
- **`Housing` → `Building`（2026-09-28 批注）**：`SpatialUnit` 第 5 级空间单元实体已由「住房 `Housing`」改为「建筑（楼栋）`Building`」；"住房" = 建筑性质为住宅的 `Building`（`buildingNature` = 住宅）。文中凡 `SpatialUnit.Housing` 一律改读 `SpatialUnit.Building`；`Housing` 不再作为类存在。`OldBlock` 新增子类 `OldCommercialBlock` / `OldResidentialBlock`。「高层民用建筑」不建对象，由 `buildingNature` + `floorCount` 筛选（`HighRiseBuilding` 对象已删除）。
- **`DataObject` 为角色类（2026-09-29 决议 A，F1 闭环）**：`computedFrom` 值域若写死 `DataObject`，会与「复用实体不新建 `DataObject`」（2026-09-24 决议）冲突——指标 1/16/17/18/24–26/40/41/52/54/55 的输入项实为 `SpatialUnit` / `RenewalObject` / `Problem` / `RenewalProject` 实例。故 `DataObject` 定位为**角色类**，值域取并集（见 §三 第 7 条）；复用实体经此合法进入值域，`55项基础指标_录入模板.md` 所填内容**无需回改**。
- **`DataObject.dataSource` 本期不绑定 CIM**：数据统一管理是否由 CIM 承担尚未定，故 `dataSource` 仅作通用来源标注，导出 `.ttl` / `.shacl` 时不预设 CIM 命名空间分支（待数据治理架构确定再扩展）。
- **`HistoricalBuilding` 独立于 `Building`（2026-09-28 批注·第四次）**：历史文化街区 / 历史建筑为**保护对象**语义实体（承载挂牌建档 / 空置等认定属性），**不并入 `SpatialUnit.Building`、不作其子类、不由属性筛选**；与「高层民用建筑」（纯物理属性筛选、不建对象）的处理**相反**。其与被保护建筑本体"一体两面"，经 `physicalCarrier` 关联 `SpatialUnit`。
- **新增支撑类来源【待核】（2026-09-29 借鉴同事成果）**：`ProblemCause` / `TemporalTrend` / `ProblemIndicatorMapping` / `problemCategory`（经济/社会/生态）/ `severity` / `causeType` 均借自同事本体，其**分类与阈值来源为学术口径 + 内部 DB，无标准条款号**，一律标【待核】，**不得作为官方依据引用**。
- **`FormulaType` / `CollectionMethod` 为受控词表（本期备用）**：`Indicator.formula`、`DataObject.dataSource` 本期仍用字符串；**已决议（2026-09-30 大王批注）：切换时机 = 步骤 3 机读序列化**。
- **同事指标编号体系与我方不一致（2026-09-29 实测）**：同事 `indicatorSequence` 为 60 项制（如 #35=道路网密度、#52=燃气管网改造率），与我方官方 55 项（#30=道路网密度、#47=燃气管网改造率）**编号不同**；凡引用同事"#N"须**整体重编**至我方编号。
- **管理对象 `ManagementObject`（原「记录对象 `RecordObject`」）收纳范围已扩展（2026-09-30 大王批注）**：`RiskyConstructionWorks`（危险性较大分部分项工程）、`UrbanOperationPlatform`（城市运行管理平台）由原「事件对象 / 设施对象」移入**管理对象**；2026-09-30 决议由「记录对象 `RecordObject`」更名「管理对象 `ManagementObject`」（现收纳「记录 / 台账 / 管理」类对象）。影响 `.ttl` 的 `rdfs:subClassOf` 与后续 SHACL `sh:targetClass`。
- **样本成果引入的改动（2026-10-09 大王批注，A/B/C1 组）**：① 新增中介类 `RemediationSuggestion`（含 `suggestionText` / `treatmentType` / `locationDescription` 属性，`proposes` / `leadsTo` / `assignedTo` / `actsOn` 关系）；② `Problem` 增 `problemDescription`、`locatedIn`（不参与传递）、`derivedFrom`，`severity` 数值化 [0,1]；③ 新增分类轴 `IndicatorCategory` + `inCategory`（13 类，见 `概念清单.md` §十-1）。**C2/C3/C4/C5 暂不执行**。
- ⚠️ **地方交付物风险（2026-10-09）**：上述改动中，`suggestionText` / `treatmentType`（限时解决·尽力解决）/ `assignedTo`（责任单位）/ `problemDescription` 的字段语义均源自样本件，**无标准条款号**，标【地方实操】，**只作结构逻辑参考，不得当标准依据**（项目规则 1）；写入本体后统一带 `sourceType = 地方实操` 标注。其中 `treatmentType` 的枚举**判定规则未明【待核】**（样本件未解释同标两值的含义）。
- **`IndicatorCategory` 取值口径（2026-10-09 大王批注）**：按**我方 55 项序号（1–55）**给出 13 类，取自 2026-10-09 批注；**分类轴跨维度独立**（不绑定 `Dimension`）；「小区（社区）」板块（9–18）合并划类。⚠️ 与2025 版工作手册编号（住房 1–9 / 社区（小区）10–21 / 街区 22–29 / 城区 30–60 + T）**不可互引**。
- **`triggers` 语义变更的连带影响（2026-10-09）**：`Problem` 与 `RenewalProject` 之间新增中介层后，`triggers` 降为兼容直通路径。影响后续 `.sparql` 闭环回溯模板——须同时支持「直通」与「经建议」两条链；`类与层级.md` §三 闭环图已同步（`triggers` 以虚线表兼容）。
- **整治区域粒度风险（2026-10-09）**：`RemediationSuggestion.actsOn` 的整治区域常为"全市""火车站附近""青年路两侧"等**非标准空间单元**，短期以 `locationDescription` 字符串兜底，长期待空间单元体系定稿后再规范。
